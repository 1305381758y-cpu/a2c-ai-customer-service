# A2C 智能客服后台设计系统规范

版本：V2.0
日期：2026-07-12

## 1. 设计原则

- 以任务为中心：先让用户找到下一步，再展示完整信息。
- 信息分层：默认显示决策信息，详情放抽屉、折叠区或二级页面。
- 状态可解释：每个异常都说明原因和处理动作。
- 密度可控：表格控制在 6–8 列，长文本省略，复杂动作收进更多操作。
- 统一反馈：加载、保存、失败、成功、无权限使用同一套组件。
- 中文后台：A2C、Telegram、WhatsApp、MiniMax、DeepSeek、Gemini、CSV、Excel 等品牌或格式可保留，其余操作文案中文化。

状态含义固定：绿色为已启用/成功，黄色为待处理/检测中，红色为失败/删除/高风险，蓝色为当前选中/主要操作。

### 字体

- 页面标题：24px，行高 32px，字重 750。
- 模块标题：18px，行高 24px，字重 700。
- 正文和表单：14px，行高 22px。
- 表格：13px–14px，行高 20px。
- 辅助说明：12px–13px，行高 18px。
- 禁止使用负字距，标题不超过 30px。

### 间距和尺寸

只使用 4、8、12、16、24、32、48px 间距。

- 页面内边距：24px，窄屏 16px。
- 模块间距：24px。
- 卡片内边距：20px。
- 表单项间距：16px。
- 输入框高度：38px。
- 普通按钮最小高度：36px。
- 图标按钮：32px 或 36px，必须提供悬浮提示。
- 卡片圆角：8px；抽屉和弹窗最多 12px。

## 3. 组件规范

### 页面外壳

`PageShell` 必须包含标题、说明、当前商户/时间状态和主要操作。页面主体只能有一个主滚动容器，工作台内部再建立区域滚动。

### 数据表格

`DataTable` 统一处理加载中、失败、空数据、无搜索结果、分页、列省略和行点击。默认不把内部 ID、原始 JSON、完整提示词放在表格中。

### 筛选栏

`FilterPanel` 统一支持关键词、商户、国家、客服账号、状态、语言、开始时间、结束时间。时间输入使用 `datetime-local`，查询区间统一转换为数据库 UTC。

### 状态标签

内部字段必须映射中文：`WAIT_REGISTER` 显示“等待注册”，`WAIT_TG_USERNAME` 显示“等待 Telegram 用户名”，`WAIT_VERIFY` 显示“核实中”，`COMPLETED` 显示“已完成”。

### 抽屉

详情抽屉用于客户资料、完整意图、模型请求、复盘和原始错误。抽屉必须能关闭、独立滚动、保留当前列表位置。

### 高风险确认

弹窗必须显示标题、影响范围、取消和确认按钮。确认按钮使用危险色，文案使用具体动作，例如“确认彻底删除客户”。

## 4. 会话工作台规范

桌面端使用 `280px / 320px / minmax(0, 1fr)` 的客服账号、客户、聊天区域；辅助区以抽屉覆盖或窄栏出现，不压缩聊天主体。客户栏可收起到 48px，辅助区可完全隐藏。

聊天区从上到下：客户摘要、流程状态、消息时间线、固定输入区。原文、中文译文、发送状态、失败原因分层展示，链接和媒体使用独立附件行。

## 5. 响应式规则

- ≥1440px：完整工作台，辅助区默认可见但不超过 360px。
- 1024–1439px：辅助区默认收起，账号栏和客户栏可折叠。
- <1024px：切换为单主区，列表通过抽屉打开，禁止三栏硬挤。
- 所有长列表必须能滚动到底；页面底部操作不能被固定头部遮挡。

## 6. 可访问性和反馈

- 键盘可访问，按钮有明确文本或 Tooltip。
- 所有异步按钮显示处理中并禁止重复提交。
- 错误信息不得只显示 `Error`、`undefined` 或英文原始堆栈。
- 空状态必须提供下一步动作。
- 状态变化后同步更新列表、统计和详情，不依赖用户刷新页面。
