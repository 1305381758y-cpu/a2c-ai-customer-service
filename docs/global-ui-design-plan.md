# 全局 UI 设计优化方案

## 1. 设计目标

本项目是运营型智能客服后台，不是营销官网。界面应优先服务高频操作、快速定位问题、稳定处理客户，而不是追求装饰感。

目标：

- 不拥挤：减少同屏无序信息堆叠，重要信息优先展示，次要信息收起。
- 排版清晰：页面统一为“页面标题 -> 筛选/操作 -> 主内容 -> 详情/抽屉”的结构。
- 操作明确：所有按钮点击后必须有加载、成功、失败反馈。
- 多角色一致：商户端和管理端使用同一套视觉语言，但信息密度和权限入口不同。
- 数据可信：统计、时间、筛选、分页、导出等功能状态必须可见。
- 全中文：后台显示文案默认使用中文，不在页面中暴露英文技术词。

## 2. 全局视觉规范

### 2.1 布局尺寸

- 左侧导航宽度：`240px`，内容不足时不压缩，移动端改为顶部导航或抽屉。
- 页面内容最大宽度：
  - 数据表/配置页：不限制最大宽度，使用全宽。
  - 表单页：主体内容建议 `960px - 1200px`，避免输入项横向拉满。
  - 会话工作台：使用全屏工作台布局，禁止普通卡片式堆叠。
- 页面左右内边距：桌面端 `24px`，窄屏 `16px`。
- 卡片间距：`16px`，表单组间距 `20px`。

### 2.2 色彩

- 主色：蓝色，用于主要操作、选中态、链接、重要状态。
- 成功色：绿色，只用于可用、已连接、成功、已启用。
- 警告色：橙色，用于待处理、配置不完整、待审核。
- 危险色：红色，只用于删除、失败、停用、高风险操作。
- 背景：浅灰，不使用大面积纯白造成边界不清。
- 禁止：大面积单一绿色、过强渐变、过多描边卡片嵌套。

### 2.3 字体层级

- 页面标题：`28-32px`，仅用于页面主标题。
- 区块标题：`18-20px`。
- 卡片标题：`15-16px`。
- 表格和列表正文：`14px`。
- 辅助说明：`12-13px`。
- 禁止在表格、筛选器、按钮里使用过大字号。

### 2.4 组件规范

- 按钮：
  - 主操作只保留 1 个高亮按钮。
  - 次要操作使用描边按钮。
  - 删除使用红色按钮，并二次确认。
  - 所有异步按钮显示“处理中/保存中/同步中”。
- 筛选器：
  - 默认一行展示核心筛选。
  - 高级筛选放入“更多筛选”折叠区。
  - 时间筛选统一使用“开始时间 + 结束时间”，包含时分秒。
- 表格：
  - 必须有分页、总数、空状态。
  - 列过多时使用“基础列 + 展开详情”，不要横向堆满。
  - 操作列固定在右侧。
- 表单：
  - 分组展示，不超过 2 列。
  - 密钥、链接、长文本使用专门输入样式。
  - 保存区固定在底部或区块右上角。
- 抽屉/详情：
  - 列表页点击行后打开右侧详情抽屉。
  - 详情过长必须内部滚动，不影响主页面。

## 3. 全局页面框架

建议统一为三类页面模板。

### 3.1 数据列表页

适用：客户、会话、接管、意图学习、模型调用、样本/素材列表。

结构：

1. 页面标题和说明。
2. 核心指标或状态摘要。
3. 筛选工具条。
4. 表格或列表。
5. 右侧详情抽屉。

重点规则：

- 列表和详情并排时，左侧列表宽度固定或可拖动，右侧详情独立滚动。
- 筛选结果必须显示“共多少条 / 当前第几页”。
- 导出按钮放在筛选区右侧，不和数据行操作混在一起。

### 3.2 配置表单页

适用：设置、Agent 配置、商户配置、国家配置、A2C账号、邀请码池、TG链接池。

结构：

1. 配置状态总览。
2. 分组配置卡片。
3. 检测/同步/保存操作。
4. 配置结果反馈。

重点规则：

- 不同配置不要堆在同一张大卡里。
- 密钥类配置和业务规则类配置分开。
- 状态检测必须展示“未配置/检测中/可用/失败原因”。
- 同步类操作必须显示最后同步时间和同步结果。

### 3.3 工作台页

适用：会话、模拟训练。

结构：

1. 左侧账号列表。
2. 中间客户列表。
3. 主对话区。
4. 右侧辅助信息区。

重点规则：

- 客户列表可以收起。
- 右侧 AI 助手、客户资料、工单、历史记录用标签页，不全部展开。
- 对话区底部输入框固定，不被页面滚动挤压。
- 消息原文/译文用紧凑上下结构，禁止大块留白。

## 4. 商户端页面优化方案

### 4.1 总览

问题：

- 指标较多时容易平铺成很多卡片。
- 今日/昨日/筛选时间的概念容易混在一起。

优化：

- 顶部放“时间模式 + 时间筛选”。
- 指标按三组展示：
  - 全量：客户总数、会话总数、客户消息总数、已回复消息总数、平均每会话消息数。
  - 今日/昨日：新增客户、会话、客户消息、回复、平均消息数。
  - 筛选时间：同一组指标。
- 支持切换“北京时间/国家时间”，切换后统计和页面显示必须一起变。

### 4.2 模型调用

问题：

- 目前类型明细和供应商明细容易被表格挤压。
- 失败原因不够突出。

优化：

- 顶部筛选：供应商、调用类型、开始时间、结束时间。
- 指标卡：总调用、成功、失败、成功率、平均耗时。
- 下方三块：
  - 按类型统计。
  - 按供应商统计。
  - 失败原因排行。
- 点击某个调用类型后，用右侧抽屉展示该类型下的供应商、模型、最近错误和最近调用时间。

### 4.3 训练中心

问题：

- 素材、样本、知识库入口过多，小白用户不知道上传什么。

优化：

- 商户端只保留一个“训练中心”入口。
- 页面分为：
  - 上传区：上传话本、聊天记录、截图、文档。
  - 解析结果：已生成样本、知识、待确认内容。
  - 审核区：可加入正式训练或忽略。
- 样本、素材、知识库作为高级视图折叠，不作为主导航暴露给普通商户。

### 4.4 模拟训练

优化：

- 左侧：模拟客户信息、国家、客服账号、语言、模式开关。
- 中间：模拟对话框。
- 右侧：当前流程节点、识别意图、命中的话本、模型调用结果。
- 明确标识“不会真实发送 A2C”。
- 2 分钟跟进在模拟模式必须走内部模拟，不触发真实接口。

### 4.5 Agent 配置

优化：

- 分为四组：
  - 人设：名称、角色、语气。
  - 目标：核心目标、完成条件。
  - 边界：禁止事项、不确定问题口径。
  - 接管：触发人工条件。
- 增加“预览语气”按钮，用三条示例问题展示当前人设效果。

### 4.6 话本流程

问题：

- 节点列表和编辑区容易挤在一起。
- 节点状态不够直观。

优化：

- 左侧：流程列表。
- 中间：流程节点时间线。
- 右侧：节点编辑抽屉。
- 节点用中文编号和名称展示，禁止显示内部英文步骤。
- 每个节点展示：
  - 节点目标。
  - 客户常见表达。
  - 标准话术。
  - 是否发送注册链接。
  - 是否发送邀请码。
  - 是否发送注册教程图片。
  - 下一步条件。
- 系统内置 11 步可复制为商户流程；复制后必须与内置话术和推进规则一致，且可编辑、可删除。

### 4.7 意图学习

优化：

- 顶部筛选：状态、建议意图、国家、关键词、时间。
- 列表列：客户原文、当前识别、建议意图、出现次数、最近时间、状态。
- 详情抽屉展示历史样例和处理按钮：
  - 采纳。
  - 忽略。
  - 加入训练中心。

### 4.8 客户

优化：

- 默认筛选当天，可改时间范围，支持时分秒。
- 搜索框支持客户账号、昵称、客服账号、手机号、TG、WS。
- 点击客户打开右侧详情：
  - 基础资料。
  - 该客户所有会话。
  - 记忆文件。
  - 删除客户。
- 删除客户必须明确提示会删除该客户所有会话和消息。

### 4.9 会话

优化：

- 使用四栏工作台：
  - 客服账号列表。
  - 客户列表。
  - 对话区。
  - 辅助区。
- 客服账号和客户列表显示未读红点。
- 客户列表支持收起。
- 对话区只保留必要信息，原文/译文紧凑展示。
- 右侧辅助区默认只开一个标签：
  - AI助手。
  - 客户资料。
  - 工单。
  - 历史记录。
- 对话复盘默认折叠，不遮挡对话。

### 4.10 接管

优化：

- 接管列表按状态分栏：待处理、处理中、已完成。
- 每条显示：客户账号、国家、客服账号、接管理由、最近消息时间。
- 点击进入会话详情，不重复做一套详情页。

### 4.11 设置

优化：

- 分组：
  - AI 供应商。
  - A2C 配置。
  - 国家/市场。
  - 智能回复开关。
  - 注册教程图片。
  - 客服账号与邀请码池。
  - TG 导师链接池。
  - Telegram 接管通知。
- A2C账号列表单独分页，不要在设置页内无限拉长。
- 邀请码池和 TG 链接池使用表格 + 抽屉编辑。

## 5. 管理端页面优化方案

### 5.1 管理端总览

- 展示平台级数据：商户总数、启用商户、今日客户、今日会话、模型调用、失败调用。
- 支持按商户、国家、时间筛选。
- 平台总览不要混入单商户配置操作。

### 5.2 商户管理

优化：

- 左侧商户列表，右侧详情。
- 创建商户用分步弹窗：
  1. 商户基础信息。
  2. 国家和默认语言。
  3. 管理员账号。
  4. 初始配置。
- 商户详情标签页：
  - 基础信息。
  - 国家。
  - 配置。
  - 用户。
  - 客服账号。
  - 数据概览。

### 5.3 后台账号

- 支持按商户、角色、状态搜索。
- 创建/重置密码/停用放在行操作。
- 不在表格中直接铺开所有字段。

### 5.4 全局会话和客户

- 与商户端保持一致，但增加商户筛选。
- 默认不进入某个商户的业务配置编辑。

### 5.5 全局训练/话本

- 平台管理员可以查看所有商户数据。
- 编辑时必须明确显示当前商户，避免误改。

## 6. 响应式规范

### 6.1 桌面端

- 大于 `1280px`：使用多栏工作台。
- `1024px - 1280px`：右侧辅助区可折叠。
- 小于 `1024px`：列表和详情改为上下结构或抽屉。

### 6.2 滚动规则

- 页面主滚动只保留一个。
- 工作台内部可有独立滚动区，但必须固定高度。
- 表格内部滚动时，表头固定。
- 所有需要向下滚动的页面都要做滚动测试。

## 7. 交互反馈规范

所有交互必须有反馈：

- 保存：保存中 -> 保存成功/失败。
- 同步：同步中 -> 同步结果数量/失败原因。
- 删除：确认弹窗 -> 删除中 -> 删除完成。
- 检测配置：检测中 -> 可用/失败原因。
- 上传：上传中 -> 解析结果 -> 可编辑草稿。
- 启用流程：启用中 -> 当前启用流程更新。

禁止：

- 点击后页面无变化。
- 操作失败只在控制台报错。
- 保存后页面状态不刷新。

## 8. 第一阶段落地优先级

建议先做 4 个高影响页面：

1. 设置页：拆分配置组，修复 A2C、邀请码池、TG 链接池拥挤问题。
2. 会话页：四栏工作台、客户列表收起、右侧辅助区标签化。
3. 话本流程：流程时间线 + 右侧节点编辑抽屉。
4. 总览和模型调用：统一指标卡、时间筛选、明细表格。

第二阶段：

1. 客户页。
2. 意图学习。
3. 训练中心。
4. Agent 配置。
5. 管理端商户管理。

## 9. 验收标准

每个页面优化完成后都必须满足：

- 页面没有明显横向溢出。
- 窄屏下核心操作仍可使用。
- 需要滚动的区域可以正常滚动到底部。
- 所有按钮点击后有反馈。
- 数据列表有分页、总数和空状态。
- 时间显示和筛选遵循当前时间模式。
- 页面不出现未翻译英文操作文案。
- 删除、启用、同步、检测等操作后状态立即刷新。
- 会话、客户、设置这类高频页面不遮挡关键信息。

## 10. 建议的技术落地方式

- 抽出统一布局组件：
  - `PageHeader`
  - `PageToolbar`
  - `MetricCard`
  - `DataTable`
  - `DetailDrawer`
  - `SettingsSection`
  - `WorkspaceLayout`
- 先统一 CSS token，再逐页迁移。
- 不建议继续在 `main.tsx` 里堆大型页面，应逐步拆成独立目录。
- 每改一个页面，用 Playwright 做：
  - 桌面截图。
  - 窄屏截图。
  - 滚动到底部测试。
  - 关键按钮点击测试。

## 11. 设计系统与视觉 Token

为了避免每个页面风格不一致，需要先统一基础设计 Token。

### 11.1 颜色规范

建议统一为 SaaS 后台风格，避免页面颜色过多。

- 主色：用于主按钮、激活状态、重点操作。
- 成功色：用于已启用、已完成、发送成功。
- 警告色：用于待处理、配置异常、同步中。
- 危险色：用于删除、停用、失败、高风险。
- 背景色：用于页面整体背景。
- 卡片色：用于内容区块。
- 边框色：用于分割线、输入框、表格边框。
- 次级文字色：用于说明、备注、时间、辅助信息。

禁止：

- 每个页面单独定义颜色。
- 同一个状态在不同页面使用不同颜色。
- 大面积使用高饱和颜色，导致页面廉价感。

### 11.2 字体和字号规范

建议统一字号层级：

- 页面标题：`24px / 28px`。
- 模块标题：`18px / 20px`。
- 表单 Label：`14px`。
- 正文内容：`14px`。
- 表格内容：`13px / 14px`。
- 辅助说明：`12px / 13px`。
- 按钮文字：`14px`。

禁止：

- 页面标题过大。
- 表格文字过小。
- 同级标题字号不一致。
- 英文、中文混用时行高不一致。

### 11.3 间距规范

统一使用 8px 间距系统：

```text
4px
8px
12px
16px
24px
32px
48px
```

推荐：

- 页面左右内边距：`24px / 32px`。
- 卡片内边距：`20px / 24px`。
- 卡片之间间距：`16px / 24px`。
- 表单项之间间距：`16px`。
- 页面模块之间间距：`24px / 32px`。

禁止：

- 页面元素贴边。
- 表单项过密。
- 不同页面卡片间距不一致。

## 12. 页面状态规范

每个页面必须补齐完整状态，不允许只有正常数据状态。

### 12.1 必须支持的页面状态

每个数据页面都要有：

- 加载中状态。
- 空数据状态。
- 加载失败状态。
- 无权限状态。
- 搜索无结果状态。
- 操作成功状态。
- 操作失败状态。
- 局部刷新状态。

### 12.2 空状态规范

空状态不能只显示空白。

示例：

```text
暂无会话数据
当客户开始发送消息后，会话会显示在这里。
```

或者：

```text
暂无 Agent 配置
你可以使用默认模板快速创建一个接待 Agent。
```

空状态建议包含：

- 空状态标题。
- 简短说明。
- 下一步操作按钮。
- 可选插图或图标。

### 12.3 错误状态规范

错误状态必须告诉用户发生了什么，以及下一步怎么做。

示例：

```text
加载失败
网络或服务异常，请稍后重试。
[重新加载]
```

禁止：

- 页面白屏。
- 控制台报错但页面无提示。
- 只显示 `Error` 或 `undefined`。

## 13. 权限与角色可见性规范

不同角色看到的页面和操作必须清晰区分。

### 13.1 平台管理员

可见：

- 所有商户。
- 全局配置。
- 全局会话。
- 全局训练数据。
- 所有 Agent 配置。
- 所有数据概览。

可操作：

- 新建商户。
- 编辑商户。
- 停用商户。
- 切换商户查看。
- 编辑商户 Agent 配置。
- 查看全局日志。

### 13.2 商户管理员

可见：

- 当前商户数据。
- 当前商户配置。
- 当前商户用户。
- 当前商户客服账号。
- 当前商户 Agent 配置。
- 当前商户会话和客户。

不可见：

- 其他商户数据。
- 平台级锁死规则编辑入口。
- 全局系统配置。

### 13.3 商户运营

可见：

- 会话。
- 客户。
- 数据概览。
- 话本。
- Agent 配置只读。

可操作：

- 查看会话。
- 查看客户状态。
- 查看配置。
- 不能修改核心配置。
- 不能删除数据。
- 不能停用商户。

### 13.4 无权限状态

用户访问无权限页面时，不应该跳白屏。

示例：

```text
暂无权限访问此页面
请联系管理员开通对应权限。
```

## 14. 数据密度与复杂信息展示规范

后台页面容易拥挤，需要明确数据密度规则。

### 14.1 默认信息密度

默认只展示最重要的信息。

例如会话列表只展示：

- 客户账号。
- 商户。
- 国家。
- 当前阶段。
- 最近消息。
- 自动回复状态。
- 最后更新时间。

不要直接铺开：

- 全部客户资料。
- 完整意图识别。
- 完整 Agent 判断。
- 完整消息日志。
- 完整错误堆栈。

复杂信息统一放到：

- 右侧详情抽屉。
- 详情页。
- 折叠面板。
- Tooltip。
- 查看更多。

### 14.2 表格字段规范

表格列数建议控制在 6-8 列以内。

超过 8 列时：

- 次要字段放进详情抽屉。
- 长文本做省略。
- 状态用 Badge。
- 操作用 Dropdown 收纳。

禁止：

- 表格横向滚动过长。
- 一行内堆太多按钮。
- 长文本把表格撑变形。

### 14.3 状态标签统一

状态不要直接显示内部字段。

示例：

```text
WAIT_REGISTER -> 等待注册
WAIT_TG_USERNAME -> 等待 Telegram 用户名
WAIT_VERIFY -> 核实中
COMPLETED -> 已完成
REJECTED -> 已拒绝
```

状态标签应包含：

- 中文名称。
- 颜色。
- 可选说明 Tooltip。

## 15. 导航与面包屑规范

页面层级多以后，必须让用户知道自己在哪。

### 15.1 顶部页面标题

每个页面顶部必须包含：

- 页面标题。
- 页面说明。
- 主要操作按钮。
- 可选状态说明。

示例：

```text
Agent 配置
配置当前商户的接待角色、回复风格和回答边界。
```

### 15.2 面包屑

管理端跨商户页面建议增加面包屑。

示例：

```text
平台管理 / 商户管理 / Amazon Spain / Agent 配置
```

商户端可以简化：

```text
配置 / Agent 配置
```

### 15.3 当前商户提示

所有涉及商户数据的页面，都必须明确显示当前商户。

尤其是平台管理员视角：

```text
当前商户：Amazon Spain
```

避免误改其他商户配置。

## 16. 国际化与文案规范

系统面向多国家、多语言，后台 UI 文案必须规范。

### 16.1 后台操作文案

后台中文界面不应混入未翻译英文，例如：

- `Submit`
- `Save`
- `Delete`
- `Loading`
- `Edit`
- `Cancel`

必须统一为：

- 保存。
- 删除。
- 编辑。
- 取消。
- 加载中。
- 提交。

### 16.2 客户语言与后台语言分离

客户对话语言可以是葡萄牙语、西班牙语、阿拉伯语等。

后台系统语言可以是中文。

禁止：

- 把内部中文字段发给客户。
- 把流程节点名发给客户。
- 把客户语言和后台语言混在同一个客户可见回复中。

### 16.3 多语言预览

Agent 配置和模拟训练建议支持语言预览：

- 中文后台说明。
- 客户实际收到的语言。
- 原文。
- 翻译。
- 最终发送内容。

## 17. 高风险操作确认规范

以下操作必须二次确认：

- 删除商户。
- 停用商户。
- 删除客服账号。
- 停用自动回复。
- 清空邀请码池。
- 删除话本流程。
- 覆盖 Agent 配置。
- 恢复默认模板。
- 批量删除样本。
- 批量导入知识库。

确认弹窗必须说明影响范围。

示例：

```text
确认停用该商户？
停用后，该商户下所有自动回复、会话同步和 Agent 配置将停止生效。
```

## 18. 配置变更影响提示

配置页保存前，应提示本次修改影响范围。

示例：

```text
本次修改将影响：
- 当前商户的自动回复语气
- 模拟训练回复
- 严格流程自然化表达
- 普通兜底回复
```

如果涉及高风险配置，例如关闭严格流程，需要更强提示。

## 19. 版本记录与回滚入口

重要配置页必须显示：

- 当前版本号。
- 最近修改人。
- 最近修改时间。
- 修改记录。
- 回滚按钮。

适用页面：

- Agent 配置。
- 话本流程。
- 设置页。
- 知识库配置。
- 发送规则。
- A2C 配置。
- TG 通知配置。

## 20. 性能与加载规范

后台页面不能因为数据多而卡顿。

### 20.1 列表性能

- 表格必须分页。
- 大列表必须服务端分页。
- 搜索必须防抖。
- 长列表可使用虚拟滚动。
- 图片、头像懒加载。
- 大字段不要默认加载，点击详情再请求。

### 20.2 首屏加载

首屏优先加载：

- 当前页面核心数据。
- 当前商户。
- 用户权限。
- 关键统计。

延迟加载：

- 历史日志。
- 复盘详情。
- 学习候选。
- 大量聊天记录。
- 知识库全文。

### 20.3 加载骨架屏

重要页面建议使用 Skeleton，不要只显示转圈。

适用页面：

- 会话页。
- 客户页。
- 商户详情页。
- Agent 配置页。
- 总览页。

## 21. UI 改造上线策略

不要一次性重构所有页面，建议分批灰度。

### 21.1 灰度范围

第一批：

- 内部管理员。
- 指定测试商户。
- 指定账号。

第二批：

- 低风险商户。
- 部分运营账号。

第三批：

- 全量商户。

### 21.2 回滚要求

每个新页面都要支持快速回滚旧版。

建议保留：

```text
?uiVersion=old
?uiVersion=new
```

或者通过后台开关控制。

### 21.3 发布检查

发布前检查：

- `1366 x 768`。
- `1440 x 900`。
- `1920 x 1080`。
- `1024` 宽度。
- 表格横向溢出。
- 页面底部滚动。
- 关键按钮点击。
- 保存状态反馈。
- 空状态。
- 错误状态。
- 权限状态。

## 22. Playwright 验收补充

每个页面至少跑以下测试：

```text
1. 页面正常加载
2. 页面截图对比
3. 滚动到底部
4. 搜索筛选
5. 打开详情抽屉
6. 保存表单
7. 操作失败提示
8. 无权限状态
9. 空数据状态
10. 窄屏布局
```

高频页面额外测试：

```text
会话页：
- 客户列表收起
- 右侧辅助区切换
- 聊天记录滚动
- 自动回复状态显示

设置页：
- 配置组展开收起
- 检测配置
- 保存配置
- 错误提示

话本流程：
- 点击节点
- 打开节点编辑抽屉
- 保存节点
- 启用流程
```

## 23. 最终补充原则

```text
先统一布局，再优化页面。
先抽组件，再改细节。
先解决拥挤，再做美化。
先保证可用，再提升精致。
先做高频页面，再做低频页面。
```

UI 优化目标不是单纯变漂亮，而是：

```text
更清晰
更稳定
更容易操作
更容易排查问题
更适合多商户长期扩展
```
