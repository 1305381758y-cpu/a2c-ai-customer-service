更新时间：2026-07-09

## 一句话结论

当前后台已经不是“缺几个页面”的问题，而是进入了“功能很多，但 UI 基础设施和前端结构跟不上”的阶段。

如果继续用当前方式补功能，后续还会持续出现：

- 页面遮挡。
- 不能滚动到底。
- 按钮点了没反馈。
- 操作成功但状态没刷新。
- 表格字段太多导致变形。
- 页面上出现英文或内部字段。
- 大数据量页面卡顿。
- 设置页越来越难找入口。
- 话本流程启用了但用户看不懂为什么没生效。

所以总体优化方向不是“单页美化”，而是：

```text
先统一基础组件和页面框架，再逐个重构高频页面，最后补齐验收和灰度发布。
```

## 当前项目真实状态判断

### 已经具备的能力

项目已经有不少可用能力：

- 多商户后台。
- 商户端和管理端。
- 会话工作台。
- 客户列表。
- 总览统计。
- 模型调用统计。
- 训练中心。
- 模拟训练。
- Agent 配置。
- 话本流程。
- A2C 账号同步。
- 邀请码池。
- 导师 TG 链接池。
- 严格话本流程。
- 多语言原文/译文展示。
- 自动回复、模拟训练、接管。

这说明产品方向不是空的，核心业务链路已经搭起来了。

### 主要短板

短板集中在前端工程和运营体验：

1. 页面越来越多，但还没有统一页面模板。
2. 配置越来越多，但还没有统一配置分组和保存反馈。
3. 表格越来越复杂，但还没有真正的数据表格组件。
4. 操作越来越危险，但还没有统一确认弹窗。
5. 数据越来越大，但还有页面依赖前端分页或一次性加载。
6. 多语言、多国家、多角色已经存在，但后台文案和权限状态还没有统一。
7. 会话、话本、设置这些高频页面承担了太多信息，布局容易失控。

## 根因分析

### 根因 1：缺少深模块，页面都在自己处理复杂度

当前很多页面都在自己处理：

- 加载。
- 错误。
- 空数据。
- 筛选。
- 分页。
- 保存。
- 删除确认。
- 状态刷新。
- 详情展示。
- 权限判断。

这会导致同一个问题在不同页面反复出现。

应该把这些沉淀成少量深模块：

- `PageShell`
- `DataTable`
- `FilterPanel`
- `ConfirmDialog`
- `DetailDrawer`
- `SettingsSection`
- `EmptyState`
- `ErrorState`
- `PermissionState`
- `TimeRangePicker`
- `StatusBadge`

这些模块的价值不是“少写代码”，而是让所有页面默认拥有一致行为。

### 根因 2：CSS 是补丁式累积，不是设计系统

当前已经有全局样式和变量，但还不是真正的设计系统。

问题表现：

- 某些页面可滚动，某些页面不能滚动。
- 某些表格能撑开，某些表格被遮挡。
- 某些按钮有反馈，某些按钮没有反馈。
- 有些页面右侧留白过大，有些页面又太挤。
- 会话页这种工作台页面和普通配置页用了相近的布局思路。

建议把 CSS 分层：

```text
styles/tokens.css       颜色、字号、间距、圆角、阴影
styles/layout.css       页面框架、侧边栏、顶部栏、滚动容器
styles/components.css   按钮、表格、表单、抽屉、弹窗、标签
styles/pages.css        少量页面专属布局
```

禁止继续在一个大 CSS 文件里无限追加临时规则。

### 根因 3：高频页面不是普通页面，而是工作台

会话页、话本流程、设置页都不是简单列表页。

它们分别是：

- 会话页：实时操作工作台。
- 话本流程：流程编辑器。
- 设置页：多模块配置中心。

如果继续按普通卡片堆叠页面做，就一定会乱。

应该单独定义三种页面模板：

1. 数据列表页。
2. 配置表单页。
3. 工作台页。

## 总体优化目标

### 产品目标

- 商户能快速找到要操作的入口。
- 运营能清楚知道当前客户走到哪一步。
- 管理员能看懂统计和异常原因。
- 配置修改后能知道影响范围。
- 高风险操作不会误点。
- 页面不因为数据多而卡住。

### 设计目标

- 后台视觉统一，不靠花哨装饰。
- 信息密度高，但不混乱。
- 关键按钮明确，次要信息收起。
- 所有状态都有反馈。
- 所有页面默认中文。

### 工程目标

- 页面逻辑从 `main.tsx` 拆出去。
- 通用 UI 能复用。
- 请求错误不再静默吞掉。
- 大列表服务端分页。
- Playwright 覆盖核心页面滚动和操作。
- 新页面按模板创建，不再复制旧页面。

## 统一页面模板

### 模板 1：数据列表页

适用页面：

- 客户。
- 会话。
- 接管。
- 意图学习。
- 模型调用。
- 训练记录。
- 商户管理。

标准结构：

1. 页面标题区。
2. 当前商户 / 当前时间模式 / 服务状态。
3. 核心统计卡。
4. 筛选区。
5. 数据表格。
6. 右侧详情抽屉。

必须支持：

- 加载中。
- 加载失败。
- 空数据。
- 搜索无结果。
- 分页。
- 导出。
- 点击行查看详情。
- 操作成功 / 失败提示。

### 模板 2：配置表单页

适用页面：

- 设置。
- Agent 配置。
- A2C 配置。
- AI 供应商配置。
- 国家语言配置。
- 邀请码池。
- 导师 TG 链接池。

标准结构：

1. 配置状态总览。
2. 左侧配置分组。
3. 右侧配置表单。
4. 保存前影响提示。
5. 检测 / 同步 / 保存结果。
6. 修改记录和回滚入口。

必须支持：

- 单组保存。
- 单组检测。
- 保存失败提示。
- 最近保存时间。
- 最近操作人。
- 高风险配置二次确认。

### 模板 3：工作台页

适用页面：

- 会话。
- 模拟训练。

标准结构：

1. 左侧对象列表。
2. 中间主工作区。
3. 右侧辅助区。

会话页具体结构：

- 左侧：客服账号列表，可收起。
- 中间左：客户列表，可收起。
- 中间右：聊天窗口。
- 右侧：AI 助手、客户资料、工单、历史记录，用标签页或抽屉。

必须支持：

- 每个区域独立滚动。
- 输入框固定底部。
- 右侧辅助区可收起。
- 窄屏可用。
- 未读标识。
- 操作后状态刷新。

### 模板 4：流程编辑页

适用页面：

- 话本流程。

标准结构：

1. 顶部：流程列表、上传、使用内置 11 步、启用状态。
2. 左侧：流程版本 / 草稿 / 已启用。
3. 中间：节点时间线。
4. 右侧：节点编辑抽屉。
5. 底部或顶部：启用前校验结果。

必须支持：

- 上传生成草稿。
- 使用内置 11 步生成草稿。
- 编辑节点。
- 删除节点。
- 删除流程。
- 启用流程。
- 恢复版本。
- 启用前检查断链、缺配置、跳步风险。

## 页面级优化建议

### 1. 会话页

当前优先级：最高。

原因：

- 这是运营每天最常用的页面。
- 也是最容易出现遮挡、滚动、状态不刷新、误操作的页面。

优化点：

- 固定四区：客服账号、客户列表、对话框、右侧辅助区。
- 客户列表可收起。
- 右侧辅助区默认收起或窄宽展示。
- AI 助手不要占据过大空间。
- 客户资料、工单、历史记录用标签页。
- 删除会话、标记接管、关闭自动回复必须有确认和反馈。
- 客户消息、客服回复、系统提示、失败原因视觉上区分。
- 所有时间按当前时间模式展示，但保留北京时间/国家时间切换。

### 2. 设置页

当前优先级：最高。

原因：

- 很多线上问题来自配置不清楚。
- A2C、AI、国家、邀请码、TG链接、自动回复、模拟训练都挤在一起。

优化点：

- 设置页改成分组导航。
- 每组独立保存和检测。
- 保存后明确显示“已保存 / 保存失败 / 影响范围”。
- 同步 A2C 账号要显示：
  - 最后同步时间。
  - 同步来源。
  - 新增多少。
  - 更新多少。
  - 停用多少。
  - 是否替换旧账号。
- 邀请码池和导师 TG 链接池必须分页、批量导入、批量停用。

### 3. 话本流程

当前优先级：最高。

原因：

- 这是业务流程能否正确执行的核心。
- 用户已经多次遇到“启用了话本流程但还是走兜底或跳流程”的问题。

优化点：

- 系统内置 11 步可以复制，但复制后必须清楚标记为“商户自定义流程”。
- 启用自定义话本后，页面要明确显示：
  - 当前命中的话本。
  - 当前节点。
  - 下一节点条件。
  - 是否允许使用系统兜底。
- 节点编辑必须支持：
  - 标准话术。
  - 客户问题回答策略。
  - 下一步条件。
  - 是否发送注册链接。
  - 是否发送邀请码。
  - 是否发送注册教程图片。
  - 是否发送导师 TG 链接。
- 启用前必须做流程校验，禁止断链或关键节点缺配置。

### 4. 客户页

当前优先级：高。

优化点：

- 默认按当日筛选。
- 支持时间精确到秒。
- 点击客户可查看该客户所有会话。
- 表格只显示关键字段。
- 详情放抽屉。
- 一键导出所有客户对话。
- 删除客户必须说明会删除客户资料、会话、消息、记忆、复盘。

### 5. 总览页

当前优先级：高。

优化点：

- 不再统计“活跃客户”作为核心指标。
- 展示：
  - 客户总数。
  - 今日新增客户数。
  - 会话总数。
  - 今日新增会话数。
  - 今日重复会话数。
  - 客户消息总条数。
  - 今日客户消息条数。
  - 已回复消息总条数。
  - 今日已回复消息条数。
  - 平均每会话消息数。
- 今日、昨日、筛选时间分别展示。
- 切换北京时间/国家时间后，统计口径也必须一起变。

### 6. 模型调用页

当前优先级：高。

优化点：

- 筛选支持：
  - 供应商。
  - 调用类型。
  - 开始时间。
  - 结束时间。
  - 成功 / 失败。
- 展示：
  - 总调用。
  - 成功。
  - 失败。
  - 成功率。
  - 平均耗时。
- 按类型、供应商、模型、失败原因分组。
- 点击类型查看明细，不只显示一个类型。
- 失败原因要保留请求摘要和响应摘要，便于排查。

### 7. 训练中心

当前优先级：中高。

优化点：

- 普通商户只看到“上传资料让系统学习”。
- 高级样本、素材、知识库不要拆成太多入口。
- 上传后展示：
  - 解析成功多少。
  - 待确认多少。
  - 失败多少。
  - 可加入训练多少。
- 对话资料、话本、截图要区分用途。

### 8. Agent 配置

当前优先级：中。

优化点：

- 页面改名可以考虑“接待专员配置”。
- 分为：
  - 角色。
  - 语气。
  - 目标。
  - 边界。
  - 接管条件。
- 增加多语言预览。
- 修改后说明影响：
  - 真实回复。
  - 模拟训练。
  - 复盘。
  - 普通兜底。

## 权限和角色优化

必须明确三类角色：

### 平台管理员

可看所有商户和全局数据。

必须在页面顶部显示当前商户，避免误操作。

### 商户管理员

可管理当前商户配置、用户、话本、客户、会话。

不能看到其他商户数据。

### 商户运营

默认只读配置，只能处理会话和客户。

不能删除核心数据，不能修改高风险配置。

## 中文化规则

后台默认全中文。

允许保留英文白名单：

- A2C
- Telegram
- WhatsApp
- TG
- MiniMax
- DeepSeek
- Excel
- CSV
- API

其他操作文案必须中文：

- Save -> 保存。
- Delete -> 删除。
- Edit -> 编辑。
- Loading -> 加载中。
- Error -> 加载失败。
- Submit -> 提交。
- Cancel -> 取消。

内部状态不能直接显示：

- `wait_registration` 应显示为 `等待完成注册`。
- `human_handoff` 应显示为 `人工接管`。
- `strict_flow` 应显示为 `话本流程`。

## 时间和统计规则

所有页面的时间筛选必须支持：

- 开始时间，包含时分秒。
- 结束时间，包含时分秒。
- 北京时间 / 国家时间切换。

切换时间模式后，必须同时影响：

- 页面显示时间。
- 今日统计。
- 昨日统计。
- 筛选时间统计。
- 导出数据。

不能只改显示，不改统计口径。

## 高风险操作规则

以下操作必须统一弹窗确认：

- 删除客户。
- 删除会话。
- 删除商户。
- 停用商户。
- 删除客服账号。
- 清空邀请码池。
- 删除导师 TG 链接。
- 删除话本流程。
- 启用新话本覆盖旧流程。
- 关闭自动回复。
- 开启模拟训练。
- 批量导入资料。
- 批量删除训练内容。

确认弹窗必须说明：

- 会影响谁。
- 是否不可恢复。
- 是否影响真实客户。
- 是否会停止自动回复。

## 性能优化规则

必须服务端分页的页面：

- 客户。
- 会话。
- 消息。
- 模型调用。
- 训练资料。
- 话本版本。
- 邀请码池。
- 导师 TG 链接池。
- A2C 客服账号。

必须防抖的操作：

- 搜索客户。
- 搜索会话。
- 搜索客服账号。
- 搜索模型调用记录。
- 搜索训练资料。

必须按需加载：

- 会话消息历史。
- 对话复盘详情。
- 客户完整资料。
- 大模型调用请求/响应详情。
- 训练资料全文。

## 验收标准

### 页面验收

每个核心页面必须验证：

1. 页面能正常加载。
2. 页面能滚动到底。
3. 主要按钮点击后有反馈。
4. 保存成功会刷新状态。
5. 保存失败会显示原因。
6. 空数据不是白屏。
7. 接口失败不是空列表。
8. 无权限不是白屏。
9. 窄屏不遮挡关键按钮。
10. 中文文案没有未翻译英文。

### 分辨率验收

必须检查：

- `1366 x 768`
- `1440 x 900`
- `1920 x 1080`
- `1024` 宽度

### 高频页面专项验收

会话页：

- 客服账号列表可滚动。
- 客户列表可滚动。
- 聊天记录可滚动。
- 输入框不被遮挡。
- 右侧辅助区可收起。
- 删除、接管、发送、标记已读都有效。

设置页：

- 每个配置分组可保存。
- 检测按钮真实请求。
- 错误提示明确。
- 状态保存后刷新。

话本流程：

- 可上传。

## 分阶段实施建议

目标：解决反复出现的遮挡、无反馈、状态不刷新、错误静默。

任务：

1. 建立 `PageShell`、`DataTable`、`FilterPanel`、`ConfirmDialog`、`StateView`。
2. 替换静默错误处理。
3. 统一所有高风险操作弹窗。

优先改：

- 客户页。
- 模型调用页。
- 话本流程页。

### 第二阶段：高频页面重构

目标：让运营每天用的页面真正稳定。

任务：

## 最终判断

当前系统可以继续跑业务测试，但如果目标是稳定商用，UI 和前端结构还需要系统性优化。

这次优化不应该理解为“换一套皮肤”，而应该理解为：

```text
把后台从功能堆叠状态，升级成可长期运营的 SaaS 工作台。
```

优先级最高的是基础组件、状态反馈、滚动布局、话本流程和设置页。把这些打稳后，后面继续加功能才不会越加越乱。
